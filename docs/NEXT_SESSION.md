# 次回作業：TrackNetV3パイロットのアノテーション設計

## 現在地

TrackNetV3をバレーボール用に追加学習するため、学習・検証用の連続フレームを元動画から抽出した。

正式なパイロットデータは次のとおりである。

```text
data/frames/tracknet_pilot_v2
```

- 元フレーム：2977〜3104
- 枚数：128枚
- プレー場面：目視確認済み
- 連続性：確認済み

### val

- 元動画開始時刻：約1秒
- 元フレーム：62〜181
- 枚数：120枚
- プレー場面：目視確認済み
- 連続性：確認済み

### test

既存の`evaluation_001`と`evaluation_001_final`を使用する。

## 次に検証する仮説

> 同じ連続画像へYOLO形式でアノテーションし、中心座標をTrackNetV3形式へ変換すれば、YOLOとTrackNetV3へ同じ正解情報を与えられる。

## 次回の作業順序

1. train・val画像のアノテーションルールを定義する
2. ボールあり・なし・遮蔽・画面外の扱いを決める
3. Label Studioへ画像を登録する方法を確認する
4. 少数画像でアノテーション操作を試す
5. YOLO形式の出力を検証する
6. YOLOラベルからTrackNetV3 CSVへ変換するコードを設計する
7. `Visibility=0`と`X=Y=0`の整合性を検証する
8. 画像枚数とCSV行数が一致するか検証する
9. 8連続フレーム系列を正しく生成できるか確認する

## アノテーション対象

- train：128枚
- val：120枚
- 合計：248枚

全画像を一度に処理する前に、少数画像でエクスポート形式と変換処理を確認する。

## データ管理方針

- 元動画を変更しない
- 抽出画像をリサイズしない
- 元フレーム番号をファイル名とmanifestへ残す
- YOLOとTrackNetV3へ同じ画像を使用する
- trainとvalを混在させない
- ボールなしフレームも削除しない
- 都合のよいプレーや成功例だけを残さない
- 変換後のデータを自動検証する

## 次回の完了条件

- アノテーションルールが文章化されている
- 少数画像を正しくアノテーションできる
- YOLO形式の各値を説明できる
- TrackNetV3形式への変換規則を説明できる
- ボールなしフレームの表現が決まっている
- 本番248枚へ進めるか判断できる

## 解釈上の注意

パイロットデータは同じ試合・同じ撮影条件から作られている。追加学習に成功しても、未知環境への汎化性能は示さない。

121個の重複系列を、121件の独立データとは数えない。

学習精度だけで採否を決めず、既存評価データに対するPrecision、Recall、F1、中心点誤差、追跡の途切れ、速度、VRAMを比較する。

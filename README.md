# VolleyScope

## バレーボール試合映像から戦術データを自動生成するAI分析システム

VolleyScopeは、バレーボールの試合映像から選手・ボール・コート上の位置とプレー内容を認識し、コーチの戦術判断に必要な統計を自動生成・可視化することを目指すプロジェクトです。

現在は企画・研究計画の策定段階です。本READMEに記載する機能には、今後の検証結果に応じて段階的に実装する予定のものを含みます。

## 開発背景

開発者は、大学バレーボール部でコーチを務めた経験があります。大会当日は、自チームへの指示、選手の状態確認、試合準備、対戦相手の観察などを行いながら、同時にプレーデータも記録する必要がありました。しかし、限られた人数でこれらを並行することは難しく、十分なデータを収集できないことがありました。

試合を動画として残すことはできますが、映像から次のような情報を手作業で記録するには、試合時間と同程度か、それ以上の時間が必要です。

- 誰が、どこから、どこへ攻撃したか
- 強打、フェイント、プッシュのいずれだったか
- サーブの種類と狙った場所
- セッターが誰に、どのような状況でトスを上げたか
- どの攻撃位置・コースから失点しているか
- ローテーションや得点状況によってプレー選択が変化するか

この経験から、大学バレーボール部では戦術判断に利用できる映像が蓄積されていても、人的・時間的制約により構造化されたデータへ変換できず、十分に活用されていないという課題を設定しました。

本プロジェクトでは、AIに戦術判断そのものを任せるのではなく、コーチが判断するための客観的なデータを映像から自動生成することを目指します。

## 最終目標

試合動画を入力すると、AIがプレーを構造化して記録し、ダッシュボードから次の問いへ短時間で答えられる状態を目指します。

- 各選手は、どの位置からどのコースへ、どの攻撃方法で得点しているか
- レフト、センター、ライト、バックアタックの使用比率と決定率はどうか
- 各アタッカーは、ストレート、クロス、インナーをどの程度使用するか
- クロス方向の中でも、サイドライン際・コート中央・奥など、どこへ落とす傾向があるか
- 強打、フェイント、プッシュ、ブロックアウトをどのように使い分けているか
- ワンタッチの有無によって攻撃結果がどのように変化するか
- 直接得点、ブロックアウト、ワンタッチ後の得点、レシーバーが弾いた得点はどの程度あるか
- 各選手は、どの種類のサーブを、どのゾーンへ打つか
- 自チームはどのゾーンへのサーブ、どの攻撃位置・コースに弱いか
- セッターは、ローテーション、レセプション状態、得点状況に応じて誰へトスを集めるか
- 終盤や連続失点時に、トス配分や攻撃選択が変化するか

最終的には、コーチが試合映像を何時間も見直さなくても、数分間ダッシュボードを確認することで、自チームと対戦相手の傾向を把握できるシステムを目指します。

## 想定する利用方法

大規模な設備導入を前提とせず、スマートフォンやビデオカメラで固定撮影した試合動画をPCへ読み込んで解析します。

1. 試合動画を選択する
2. チーム、出場選手、背番号、ポジションなどの基本情報を入力する
3. 最初のフレーム上でコートの四隅とネット位置を指定する
4. AIが選手・ボールを検出し、フレーム間で追跡する
5. コート上の位置、ボール軌道、選手の姿勢からプレーを認識する
6. プレーを選手・ローテーション・攻撃位置・コース・結果別に集計する
7. ヒートマップ、コース図、比較表として表示する

すべての情報を映像だけから完全自動で推定することには固執しません。コート位置や初期ローテーションなど、少量の情報を人が入力することで精度と実現可能性を高めます。AIの信頼度が低い判定については、利用者が確認・修正できる設計とします。

## 生成する戦術データ

### アタック分析

- アタッカーとポジション
- レフト、センター、ライト、バックアタックなどの攻撃位置
- 強打、フェイント、プッシュなどの攻撃種別
- ストレート、クロス、インナーなどの攻撃コース
- コート上の詳細な落下位置
- ブロッカー数
- ワンタッチの有無
- 直接得点、ワンタッチ後の得点、ブロックアウト、レシーバーが弾いた得点、被ブロック、アウト、ラリー継続などの結果
- ローテーション、得点状況、レセプション状態との関係

選手ごとに攻撃開始位置から落下位置までを矢印で示し、コース、攻撃種別、結果によって色分けします。例えば「相手7番はレフトからのクロスが多く、特にZone 5奥のサイドライン際へ決める割合が高い」「ブロックアウトが攻撃得点の何%を占める」といった傾向を可視化します。

### サーブ分析

- サーバー
- スタンディングフローター、ジャンプフローター、ジャンプトップスピンなどのサーブ種別
- サーブ開始位置
- 狙った方向と落下ゾーン
- レシーバーとレセプション位置
- エース、相手レセプションを崩した、インプレー、ミスなどの結果
- ローテーション、得点状況との関係

サーブ速度は撮影条件による誤差が大きいため、初期の主要指標には含めません。代わりに、サーブ種別、エース率、ミス率、レセプションを崩した割合、連続得点率などから、各選手の特徴を定量化します。

出力例：

> 7番はジャンプサーブ比率82%。Zone 1とZone 5を中心に狙い、相手のレセプションを崩した割合は43%。ミス率も18%と高く、ハイリスク・ハイリターン型のビッグサーバーである。

### セッター・トス配分分析

- セッター
- トス接触位置とトス到達位置
- トス先の選手と攻撃位置
- ローテーション別のトス配分
- レセプション状態別のトス配分
- 得点状況、終盤、連続失点時のトス配分
- 直前の攻撃結果と次のトス選択の関係

単純なトス本数だけでなく、「レセプションが崩れたときはレフトへ何%集めるか」「20点以降は誰へ集めるか」など、条件付きで分析します。

### 守備・失点分析

- 相手アタッカー
- 相手の攻撃位置、攻撃種別、攻撃コース
- 自チームのブロッカー数と守備位置
- ボール落下位置
- ワンタッチの有無
- レシーバーが触れずに失点したか、触れた後に失点したか
- 自チームのローテーション

「Zone 5での失点が多い」だけでなく、「相手レフトからのクロス強打に限定すると、Zone 5奥のサイドライン際での失点率が高い」という粒度で分析することを目指します。

## AI・システム構成

YOLOは映像内の物体を検出する「目」として使用します。YOLOだけで強打やトス配分まで判断するのではなく、複数の処理を組み合わせます。

| 処理 | 技術候補 |
| --- | --- |
| 選手・ボール・ネットの検出 | YOLO |
| 選手・ボールの追跡 | ByteTrackなど |
| コート座標への変換 | 射影変換（Homography） |
| 選手識別 | 背番号OCR、追跡、ローテーション、手動初期設定 |
| 身体動作の取得 | 姿勢推定 |
| ボール接触候補の推定 | ボール軌道と手・腕の位置関係 |
| サーブ・トス・攻撃種別の認識 | 時系列モデル |
| 攻撃コースの分類 | 接触位置と落下位置のコート座標 |
| 戦術データの保存 | 構造化されたイベントデータ |
| 結果表示 | ヒートマップ、コース図、クロス集計 |

## 選手識別に関する方針

選手同士の重なりや背番号の遮蔽は、本プロジェクトの主要な課題です。また、ユニフォームを着用しない練習試合では、背番号による識別が利用できません。

そのため、選手識別は単一の方法に依存せず、次の情報を組み合わせます。

- 背番号OCR
- ユニフォームの色・外観特徴
- フレーム間の追跡ID
- コート内の位置
- 初期ローテーション
- ポジションごとの移動制約
- 利用者による最初の対応付け

練習着などで外観が似ている場合には、動画の最初に選手を手動で指定する、色付きビブスを利用する、識別不能になった区間だけ再指定するなど、現実的な運用も検討します。誤った選手IDを維持し続けるより、判定不能として人に確認を求めることを優先します。

## 非学習環境に対する頑健性

画像認識モデルは、学習時と異なる体育館、照明、撮影角度、カメラ、ユニフォームなどで精度が低下する可能性があります。本プロジェクトでは、既知環境だけの精度ではなく、未知環境での性能低下を主要な評価対象とします。

### 想定する環境変化

- 未学習の体育館・背景・床・照明
- 未学習のカメラ・解像度・フレームレート・圧縮率
- エンドライン側、サイド側などの異なる撮影角度
- 異なるユニフォーム、練習着、ボール
- 遠距離、小さなボール、モーションブラー、選手による遮蔽

### 対策候補

- 複数体育館・複数撮影条件のデータで学習する
- 輝度、圧縮、ブラー、縮小、遮蔽など、現実的なデータ拡張を行う
- 高解像度入力やP2特徴層など、小物体向けの検出方法を検証する
- IoUだけでなくNWDを利用した損失関数を比較する
- 単一フレームだけでなく、前後フレームの軌道を利用する
- 新しい会場の少数ラベルによる追加学習を検証する
- 低信頼度の判定を自動確定せず、判定不能として扱う
- 必要に応じてTest-Time Adaptationを発展的に検討する

同じ動画の隣接フレームを無作為に学習・テストへ混在させると、性能を過大評価する可能性があります。そのため、データは試合・体育館・撮影角度単位で分割し、学習に使用していない環境で評価します。

## 開発計画

### Phase 0：データ・アノテーション設計

- 撮影条件と対象動画を整理する
- ボール、選手、プレーのアノテーション基準を作成する
- 強打・フェイント・プッシュ、ワンタッチ、ブロックアウトなどの定義を明文化する
- 試合・体育館単位で学習・検証・テストデータを分割する
- 手作業による正解プレーデータを作成する

### Phase 1：検出基盤

- 試合動画を読み込む
- 事前学習済みYOLOの性能を測定する
- バレーボール映像をアノテーションする
- バレーボール用YOLOを追加学習する
- 選手・ボール・ネットを検出する
- 検出結果を時刻・座標・信頼度付きで保存する
- 検出結果付き動画を出力する
- 未知体育館での精度低下を測定する

最初は分析機能よりも、プレー中の選手とボールをどの程度の精度で検出できるか、何をボールと誤検出するかを明らかにします。

### Phase 2：追跡とコート座標

- 選手とボールをフレーム間で追跡する
- コートの四隅とネット位置を設定する
- 映像座標をコート座標へ変換する
- 一時的なボール消失を前後の軌道から補完する
- 選手IDの切り替わりと追跡失敗を測定する

### Phase 3：プレー単位への分割

- サーブ開始候補を検出する
- ボールのネット通過を検出する
- 選手とボールの接触候補を推定する
- 長時間映像を内部的にラリー・プレー単位へ分割する

ラリークリップの生成だけを最終成果にはせず、後段の統計生成に必要な前処理として位置付けます。

### Phase 4：プレー分類

- サーブ種別と狙ったゾーンを分類する
- セッターとトス先を推定する
- アタッカー、攻撃位置、攻撃種別を分類する
- 攻撃コースと落下位置を算出する
- ワンタッチ、ブロックアウト、レシーバーが弾いた得点などの結果を分類する
- 自動判定・人による修正・判定不能を区別して保存する

### Phase 5：戦術統計の自動生成

- 選手別の攻撃コースと決定率を算出する
- サーブ種別、狙い先、結果を集計する
- 攻撃位置・コース別の失点傾向を算出する
- セッターの条件付きトス配分を算出する
- ローテーション・得点状況・レセプション状態別に比較する
- 複数試合を横断して傾向を分析する

### Phase 6：ダッシュボード

- 攻撃コース図
- 詳細な落下位置ヒートマップ
- サーブゾーン図
- 失点ゾーンヒートマップ
- トス配分チャート
- 選手別・ローテーション別レポート
- 自チームと対戦相手の比較画面

## 評価計画

### 検出・追跡性能

- Precision、Recall、AP50、mAP50–95、小物体AP
- ボールのフレーム単位検出率
- 照明などをボールと判定した誤検出数
- HOTA、IDF1、追跡IDの切り替わり数
- ボール軌道の欠損時間と追跡復帰時間

### プレー分類性能

- サーブ種別、攻撃種別、攻撃位置、コース、結果のPrecision・Recall・Macro-F1
- コートゾーン正解率
- 選手・アタッカー識別正解率
- クラス別混同行列
- 判定不能率

### 戦術統計の再現性

- 選手別打数・決定率の誤差
- 攻撃位置、攻撃種別、サーブ種別の構成比誤差
- 手作業で集計したトス配分との差
- 攻撃・サーブ落下分布の差
- 手作業分析とAI分析で得られた主要傾向の一致率

### 実用性

- 1試合の解析時間
- 手作業で統計を作成する時間
- AI出力の確認・修正に必要な時間
- AI支援による作業時間削減率
- コーチが必要とする分析項目を取得できた割合

## 現時点で想定する技術的課題

- 遠距離で数ピクセルになる高速なボールの検出
- モーションブラーと選手による遮蔽
- 体育館の照明、看板、顔などのボールへの誤検出
- 選手が重なったときの追跡ID維持
- 背番号が見えない選手や練習着での選手識別
- 単一カメラ映像からのワンタッチ・ブロック接触認識
- 強打、フェイント、プッシュの定義と分類
- フローター、ジャンプフローター、トップスピン、ハイブリッドサーブの分類
- 撮影角度による奥行き・速度推定誤差
- 未知体育館・未知撮影条件での精度低下

## 参考にする先行研究

- Ding, Y., Fan, Z., & Zhao, Y. (2026). *YOLO-Ball: Real-time tennis ball detection under occlusion and motion blur*. 高速・小物体の検出に対して、P2特徴、遮蔽を考慮した特徴融合、NWDとIoUを組み合わせた損失関数を提案。
- Ruan, X., & Tang, W. (2024). *Fully Test-time Adaptation for Object Detection*. ドメインシフト下での疑似ラベルの信頼性に着目し、IoUに基づくフィルタリングを提案。
- Doan, A.-D. et al. (2024). *Weakly Supervised Test-Time Domain Adaptation for Object Detection*. 操作者による弱いラベルを利用した、Human-in-the-loop型のテスト時適応を提案。
- *Advanced Volleyball Stats for All Levels: Automatic Setting Tactic Detection and Classification with a Single Camera* (2023). 単一カメラ映像からトス軌道とセッティング戦術を認識する手法を提案。
- *A Proposal of a Spike Event Classification Method Based on Ball Trajectory in a Volleyball Video* (2023). YOLOとByteTrackによる人物・ボール追跡と、軌道に基づくスパイクイベント分類を検討。

## プロジェクトの方針

- YOLOを使用すること自体ではなく、実際のコーチ経験から生じた課題の解決を目的とする
- AIの精度を一つの指標だけで評価せず、未知環境での性能と最終統計の正確性を評価する
- 完全自動化に固執せず、人による少量の初期設定・確認を合理的に組み込む
- 判定できないものを無理に確定せず、信頼度と判定根拠を残す
- 最初から研究テーマを固定せず、実装と評価を通して最大の技術的課題を特定する
- バレーボールで十分に検証した後、共通基盤を他競技へ展開する可能性を検討する
